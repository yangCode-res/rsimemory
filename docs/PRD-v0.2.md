# RSI 记忆管理 Policy 进化系统 PRD

版本：0.2　日期：2026年10月13日　状态：按确认架构实施首版；工程验证中，正式比较参数仍待冻结。

本文基于根目录 `PRD-memory-policy-rsi-v0.1.md` 与 `docs/architecture-v0.2.png`。该图已确认是本项目的 target architecture：蓝色为冻结链路和评测组件，绿色为可进化 memory policy，橙色为离线进化，红色为有效性约束。图中的结构是目标，不表示图示各组件均已实现。本文将模型工具协议、检查点批处理、基线、反思干预和安全执行要求具体化；v0.1 中未被覆盖的研究目标、患者级划分、版本谱系和成本分项要求继续有效。

目标数据流为：固定执行器将历史会话送入可进化 policy；冻结 ReAct 通过固定 `search/read` 协议获得证据并生成答案与工具轨迹；独立评分器读取隔离保存的标准答案/来源标注；评测层汇总六类性能、AVG 和成本。训练集的操作日志、成功/失败诊断驱动离线 Reflexion、定向 replay 和三个修改假设；边界检查与隔离将候选路由到失败归档或版本树/MCTS + UCT；候选比较汇总验证集成绩、成本与 Pareto 集合。target architecture 允许 policy 管理派生记忆和索引，但首轮接口与运行限制见下文。

## 1. 目标与实验范围

在固定 ReAct 回答模型、prompt、工具协议、执行器和评分器下，比较不同可进化记忆 policy 对 MedMemoryBench 的影响。policy 可以自行组织派生记忆并在内部提取、合并、更新、删除和检索；它不能改变回答链路，也不能接触答案、未来记录或评分标注。

首轮从两个 plain 原文 chunk 检索基线开始：字符 bigram BM25 与语义检索。临时 provisional config 为 chunk 长度 1200 字符、overlap 120 字符、BM25 top-k 5。两者都对原始会话按相同切分规则生成 chunk，并仅从当前检查点可见的原文 chunk 返回候选；它们是独立基线，不将摘要、图结构或其他派生记忆预先塞入基线定义。上述数值可用于 smoke，不构成正式实验冻结值。语义基线必须使用明确配置的本地 embedding 模型路径；若模型或路径不可用，跳过并标记未运行，不得以 BM25 或其他检索冒充语义结果。

初版只从根版本展开一次，反思后生成三个子代码版本。每个有效候选从空 policy 状态开始，完整 replay 训练和验证流程。违规候选记为失败进化，不得作为有效候选参与比较或价值回传。每个节点及其假设、代码、配置、运行和结果均需留档。

## 2. 固定回答协议与数据可见性

冻结 ReAct 模型使用的工具协议只有：

- `search(query, filters)`：候选纯函数返回 memory ID；宿主将可读取的命中解析为证据预览 `{id, text, session_id}` 返回给模型。
- `read(ids)`：由宿主执行器校验 ID 是否属于当前患者、当前检查点且可见，然后返回对应来源内容。

回答模型不获得创建、修改、删除、合并、导入或导出记忆的工具。模型只能通过 `search` 获取证据预览、通过 `read` 获取完整证据；policy 的写入和内部 CRUD 由固定执行器调用 policy 接口完成。工具名称、参数形状、结果形状和 ReAct prompt 对所有版本相同，具体 JSON Schema、超时与重试配置须在实验配置中冻结。`session_id` 是时间定位字段，不得附带题型、答案来源或评分 metadata。

固定执行器按历史顺序摄入会话。每个患者、每个候选的状态互相隔离。在线问题输入及模型可见的工具结果中不得包含 `query_type`、标准答案、答案来源标注、评分依据、未来记录或其他参考 metadata。执行器可在隔离的离线评分阶段使用答案和来源标注；这些数据不得写入 policy 状态或提供给回答模型。日志中题型和答案来源字段也须与在线模型输入隔离。

在一个检查点内，所有题目基于同一个已摄入会话快照独立回答。题目之间不延续题目上下文、先前答案、模型工具调用历史或写入结果；每题拥有独立的 ReAct 对话。一个检查点的查询不能让 policy 更新状态，也不能改变同一检查点其他题目可读的快照。只有检查点之间的历史会话摄入会推进 policy 状态。

## 3. 数据划分、检查点与评分

训练、验证和测试按患者划分；同一患者的全部检查点、题目、模式与语言只能属于同一集合。训练数据用于基线分析、错误与成功案例归因及候选生成；验证集用于展开后候选汇总比较。测试集保持封存，本轮不运行，也不用于生成反思、选择候选或调参。

检查点到达时，执行器先将截至该点的会话按固定顺序交给 policy，再为该快照下的全部问题独立启动回答。问题顺序不得造成记忆写入、答案传播或数据可见范围变化。Mixed 模式的辅助会话仍由固定执行器按冻结映射摄入，并纳入相同患者和快照规则。

沿用论文六类任务的二元判分。对每种模式分别计算各类准确率，再计算六类等权平均：

`AVG(mode) = (Accuracy(type_1) + ... + Accuracy(type_6)) / 6`

Efficient 与 Mixed 分别报告六类准确率、样本数与 AVG，不合并成新单一分数。首轮只运行 Efficient；Mixed 数据适配尚未接入，不能把 Mixed 报成已评测结果。缺少任一类别时，该 AVG 标为不可比较。报告同时给出患者数、题目数、运行状态和评分异常。待初轮诊断完成后，计划补跑预先定义的 no-error 诊断对照，并将其作为单独、可追溯的后续 run；不得根据候选结果临时变更对照或评分口径。

## 4. 基线和反思进化流程

固定执行器对两个基线及候选运行相同的数据时序、回答链路和评分流程。两个基线分别报告同口径的成本和性能，形成 policy 进化前的参照。

基线训练 replay 完成并经离线评分后，反思流程使用训练集失败案例与成功对照进行聚类、归因，并显式记录归因不确定性、支持/反对证据和来源引用。成功案例用于识别有效策略与边界条件。对每个高价值问题簇，提出定向干预，并可执行对应的定向 replay 检验归因；说明预期改善任务、可能退化、最小代码修改及可验证预测。反思输入中的答案与来源信息只用于离线分析，不得进入在线 policy 或回答模型。诊断 no-error 对照安排在初轮之后单独执行并单独报告。

本轮生成三个不同子代码版本，每个对应明确的修改假设。候选运行前执行静态边界检查及隔离运行；代码或运行违反接口、信息权限、文件/网络隔离等约束即标记违规失败，保存证据与原因，并停止其正式 replay。有效候选各自从空状态重放，不迁移父版本或其他候选的派生记忆。

初版 MCTS/UCT 只执行根节点的一次展开，产生三个候选。实现记录节点、边、访问次数和配置，并为后续扩展保留 UCT 所需字段；本轮不据此宣称多轮搜索效果。

## 5. 成本、报告与选择

成本不设预先阈值，也不把成本折算成 UCT 收益罚项。按版本、模式、患者/运行和阶段报告实际测得的 policy 模型调用量（输入/输出 token）、调用次数、耗时、存储字节、来源读取量，以及反思、代码生成和重试开销。回答模型与 judge 成本分列，不能并入 policy 管理成本或隐藏由返回上下文造成的变化。任何真实辅助模型调用必须经过固定计量 provider；provider 未启用时，明确记为 disabled，并禁止绕过 provider 的直接调用。无调用时报告为未启用，不得记作零成本实测。

性能与成本分开呈现。相同配置下展示六类准确率、Efficient/Mixed AVG、样本数、成本明细、运行状态和 Pareto 支配关系。初版只报告测量值及观察到的比较，不设成本淘汰阈值，不作未经重复测量支持的显著性结论。

## 6. 安全实现要求与限制

候选 policy 的目标接口为受限 Python 纯函数，仅接收和返回 JSON-compatible 数据：`initialize(config)->state`、`ingest(state,session)->state`、`search(state,query,filters)->memory IDs`。沙箱禁止任意 import、文件读写、网络、进程启动及其他副作用；policy 函数只能从输入和自身 JSON state 派生新 state 或检索结果。首轮允许 policy 在自身 state 内组织派生结构，但 `search` 只能返回宿主登记的原文来源 ID；派生文本返回与读取暂不开放，待 lineage 和派生记录 schema 实现后再启用。宿主持有原文、答案、来源标注和运行时能力。`read(ids)` 必须由宿主实施来源、患者和检查点校验。

首版候选代码只允许在 Linux 上的隔离子进程中执行，采用 AST 检查、seccomp 拒绝文件系统/网络/进程相关系统调用，并配置 `RLIMIT` 资源上限。隔离初始化、策略检查、执行或结果验证任一步骤失败都 fail closed：该候选标记失败并停止，不降级到普通 Python 执行。非 Linux 环境不得执行自动生成的候选代码。纯函数协议和 Python 语言限制本身不能构成操作系统安全边界；这些措施是计划的首版防护而非已验证的安全保证。固定执行器可继续运行不执行外部候选代码的基线工作。

受控辅助模型调用通过宿主提供的 provider 进行计量与白名单控制，可在初版推迟接入。policy 不能自行建立模型客户端或绕过 provider。工具可见性、状态大小和调用资源限制须由宿主配置并记录。

## 8. 验收标准

1. 回答模型只看见冻结的 `search`、`read` 两个工具；search 显示 `{id,text,session_id}` 预览，read 提供完整证据；模型不能调用 CRUD，prompt 与工具协议在候选间一致。
2. 在线模型输入与工具结果不包含题型、标准答案、来源标注或未来信息；离线评分可审计且与在线数据视图隔离。
3. 同一检查点所有题目使用同一 policy 快照，各题之间不传递题目、答案、对话状态或记忆写入。
4. 两个 plain 原文 chunk 基线（BM25、语义检索）使用冻结 chunk 和参数，单独报告；不可用的本地语义模型标为 skipped。
5. 训练集反思包含失败/成功聚类、归因、不确定性和定向干预；候选恰为三个子代码版本，并从空状态 replay。
6. 违规候选被标记失败且不进入有效比较；候选代码仅在独立 OS/容器隔离后执行。
7. Efficient 与 Mixed 分别报告六类等权 AVG；测试集不运行，成本先报告实际值而不设阈值。
8. 初版仅一次根节点展开；Efficient 首轮结果与后续 Mixed/no-error 计划分开标记；所有辅助模型调用经可计量 provider，或明确标记为 disabled。
